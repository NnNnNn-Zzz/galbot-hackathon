# 真机验证流程 v2（盲抓固定点版 · 不示教）

## 本版定位

用 tuning.py 里的**官方 example6 占位位姿**直接盲抓，**不采示教数据**。
目标不是「一定抓起盒子」，而是验证：**封装层→SDK→真机链路全通、
异常语义正确、全过程安全无碰撞**。抓起盒子是加分项，不是通过标准。

> 占位值出处：官方 `example6_pick_and_place.py` 的 `GRASP_POSE_BASE_PLACEHOLDER`
> = `[0.4, y, 0.65, 0,0,0,1]`，官方注释原话「Replace it with the pose produced
> by perception」——即官方也预期它是占位，但保证格式与运动学合法。

## 可行性结论

可行，依据三条：

1. **运动链路已被真机验证**：朱宁 dev 层 22/22 通过，wrapper 新接口是对同一
   SDK 调用的薄封装，无新风险点；
2. **碰撞检查兜底**：`set_arm_pose` / `move_line_to` 均开
   `enable_collision_check=True`，位姿偏差导致戳桌/碰盒时规划会拒绝，
   表现为 `failed`（走 must_run 归位），不会硬撞；
3. **官方教程同款姿势**：单位四元数 `[0,0,0,1]` 是 example6 的原装姿态，
   不是拍脑袋。

## 盲抓成功的物理前提（现场布置，代替示教）

不示教 ≠ 不测量。盲抓能否抓到，取决于**盒子是否真在剧本点上**：

| 量 | 剧本值 | 现场做法 |
|---|---|---|
| 盒中心 x | 0.40 m（base_link 前向） | 卷尺从机器人底座前沿量 40 cm，贴定位胶带 |
| 盒中心 y | -0.10 m（右侧 10 cm） | 卷尺量，贴定位胶带，盒子对十字线放 |
| 抓取高度 z | 0.75 m（桌面实测 0.72 + 盒腰约 3 cm，已标定） | 盒高异常时微调 z，每次 ≤1 cm |
| 盒宽度 | ≤ 8 cm（GRIPPER_OPEN_M=0.10） | 选窄盒；闭合到 0.02 m 需盒子 ≥ 2 cm |

摆放误差容忍：夹爪张开 10 cm，盒宽 ~6 cm → **xy 摆放误差 ≤ ±2 cm 基本能抓住**。

## 验证流程（四段递进，每段不过不往下）

### 实验 0 · 冒烟（5 分钟，无盒）

```bash
MED_IO=wrapper python3 scripts/smoke_medicine_hw.py
```

- S1 attach_tool / S2 开爪 / S3 合爪 / S4 位姿读回 / S5 播报
- 通过标准：S1-S4 全 `"success": true`，肉眼见夹爪开合一次；
  S5 允许降级（PCM 缺失则 played=False，日志可见即可）
- **整段 JSON 日志交 Agent 复核后才允许进实验 1**

### 实验 1 · 空桌盲抓（无盒，验证轨迹安全）

只跑 s0+s1（预抓取→逼近→合爪→抬起→收臂），桌面**不放盒子**：

- 通过标准：无碰撞告警、无急停、各步 success；s1 返回 picked=False/None 属预期
- 观察点：预抓取位（0.35,-0.10,0.85）是否悬在桌面上方合理高度；
  逼近段是否垂直下探 5 cm；收臂是否到位
- 若 move_line_to 反复 failed：大概率 z 仍低于盒腰或触及桌面触发碰撞检查，
  把 GRASP_POSE z 每次 +0.01 重试（这就是盲抓版的「现场调参」，只调 z 一个轴）

### 实验 2 · 单盒盲抓（放 1 个盒在定位点）

- 盒子按上表定位胶带摆放，重复实验 1
- 通过标准：盒子离桌即成功；没抓住但流程走完也算**链路通过**，
  拍照留证帧（`grasp.pre_image`）用于复盘偏差方向
- 偏差修正优先级：先重摆盒 → 再调 z → 最后才动 x/y（每次 ≤1 cm）

### 实验 3 · 全流程低速

完整 7 步（s0→s6），底盘距离不变但速度依赖 SDK 默认；一人持急停待命：

- 通过标准：9 步 trace 全 ok；failed 路径也必须观察到 must_run 归位执行
- 播报段 PCM 缺失时确认日志有「播报降级」警告而非假成功

## 技术细节备忘

- 环境：PC 侧 `source ~/galbot/galbot_sdk/linux-x86_64-gcc940/setup.sh`，
  PC 与机器人同 LAN；`MED_IO=wrapper`，**不要**设 `GALBOT_MOCK=1`
- 进程纪律：SDK destroy 后同进程不能再 init，每轮实验重起进程
- 超时：底盘 set_base_pose 30s（朱宁实测放宽后）；`robot.init()` 无真机时
  约 127s 才返回，脚本别设短超时
- 异常语义：failed → 仍执行归位；unknown → 立即全停不归位（团队规定，
  真机上看到 unknown 不要慌，是设计行为）
- 留证：s1 抓取前自动拍一帧存 `logs/frames/`，日志 key `grasp.pre_image`

## 与下一版（VLM 校验）的衔接
