# 2026-11-07 拉抽屉示教记录

本记录覆盖已对位的右夹爪闭合把手，以及右手末端分八段向机器人后方移动。首次目标 25 cm，现场随后要求再拉 5 cm，最终末端 X 相对拉动起点后移 30.11 cm。底盘没有收到运动指令。现场人员报告扶稳抽屉，并在追加 5 cm 前确认还有行程。

## 实际操作

起始对位由现场人工完成，未记录机器人从其他位置走到把手的动作。夹爪命令为 `side=right, width=0.020 m, speed=0.020 m/s, effort=10`；SDK 返回 `ControlStatus.SUCCESS`。反馈开度从约 50.0 mm 收至 24.3 mm，受力读数从约 2.9 升至约 8.2。腕部画面显示把手处于两指之间。

拉动使用控制台的 `motion.move_end_effector_offset`，坐标系为 `base_link`。每段以累计 X 目标计算负 X 偏移，同时用当前读数修正目标 Y、Z，`roll/pitch/yaw` 均传 0。命令启用 SDK 碰撞检查，但它是末端**位姿目标**接口，不保证两次采样之间严格走直线。每段均读取实际末端、夹爪和底盘状态。25 cm 处由于 Z 超出 5 mm 门槛停止右臂；现场确认后，以当时实际高度作为追加 5 cm 的新基准。30 cm 处再次超差，右臂停止命令返回 `ControlStatus.SUCCESS`。

## 复刻边界

可复刻的是**夹爪参数、八段目标与逐段复核方式**。本次没有连续关节/TCP 轨迹、直接力矩或力传感器记录，也没有独立标定的抽屉滑轨开度；相机和 SDK 时间没有硬同步，无法从离散快照还原每段中间路径。事后检查控制台日志，只找到八条末端运动 HTTP 请求记录，没有中间轨迹采样。末端 Y、Z、姿态实际未保持恒定，不能把这批数据标成严格直线示教。人工扶稳的力与接触点未量化。

未来场景需先确认同一抽屉、底盘与右臂起点、把手对位、夹持和现场人员扶稳，再逐段执行并监测。当前 `sdk_wrapper` 尚缺真实抽屉状态、末端位姿控制和停止接口，场景入口会在下发任何动作前拒绝；离线 mock 通过不等于真机复刻验收。自动对位、取药、推回抽屉、松爪和撤手不属于这次拉屉示教，不能由本记录推导为已验证动作。

## 下次示教的连续采集

需要在动作开始前启动 `medicine_frontend/tools/record_drawer_stream.py`，动作结束后按 `Ctrl+C`。它只读取 8080 控制台已有的关节、底盘、夹爪事件流，并以最多 10 Hz 查询右手 TCP；每条保存接收时间，事件原有时间戳也保留。结果写入新的 `teaching/drawer_*/continuous/`，包括两份 NDJSON、计数与 SHA-256 清单，清单登记到 SQLite。该工具不发送夹爪、手臂或底盘运动命令。运行前需把**当前有效**控制台访问码放入进程环境变量 `GALBOT_CONSOLE_CODE`，不要写入命令历史或文件。建议采集同时继续保存四路相机图像与时间戳；连续状态和相机仍需检查时钟偏差及对齐质量。

```powershell
python -X utf8 -m medicine_frontend.tools.record_drawer_stream --session drawer_next_YYYYMMDD_HHMMSS --duration-s 600 --tcp-hz 10
```

这只能记录**下一次**示教，无法补出本次八段动作之间已经过去的状态。即使补采，复刻前仍需核验接触、受力、行程和安全停止；仅凭轨迹不能证明抽屉滑轨或机械臂的受力条件相同。
