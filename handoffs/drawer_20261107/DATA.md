# 数据边界与索引

## 静止点

总索引：`medicine_frontend/data/medicine_dataset/teaching/pregrasp_to_initial_20261107_200135/manifest.json`。

每点的 `states.ndjson` 是直接 SDK 读取的数值关节/夹爪样本，原始设备时间戳保留。相机文件在同数据根目录的 `raw/head/<session>/` 与 `raw/wrist/<session>/`，相机元数据与 manifest 引用路径相对于数据根目录。数据中的原 Windows 绝对路径只作来源记录，迁移后使用这些相对索引。

P0 的业务标签已由用户更正为“夹取前准备”，历史目录名仍保留 `grasp_capture`，避免破坏引用。P1 首次状态读取超时，随后补采成功；P2 右腕第一次连接断开，重试成功。最终数值状态分别为 50/20/20 帧，无采集报错。

画面与关节不是同一时刻采集，头部与腕部也先后采集，间隔可达分钟。停稳是现场操作约定，不是由本工具认证的。腕部深度存在 `depth_error_or_stale` / `rgb_depth_skew`；部分头部 RGB 有 `stale_rgb`。这些深度不能用于未验证的精确几何。相机元数据里的 `joint_state_not_numeric` 描述相机桥自身返回的数据，不表示独立 `states.ndjson` 中的数值关节样本缺失。外参仍有 `geometry_calibration_unverified` 标记。

本批关键点没有独立记录 TCP 和 map 底盘位姿，不能宣称已经完成基座标定；需要时应结合对应机器人模型做 FK，并核对工具坐标系、底盘与躯干姿态。实际关节配置可以区分同末端位姿下的不同 IK 解，但它不能证明点间插值路径无碰撞。

## 拉屉过程

三个关联会话：`drawer_final_20261107_121006`（对位）、`drawer_grip_verify_20261107_121348`（夹持）、`drawer_pull_20261107_122158`（八段拉动）。最后一个目录内的 README、demonstration.json 和 pull_record.json 是主要入口。

累计目标为 2、7、12、17、22、25、27.5、30 cm。末端最终 X 后移约 30.114 cm，Y 偏移约 −7.19 mm，Z 偏移约 −17.03 mm，姿态变化约 3.39°。这是 TCP 位移，不是独立测量的抽屉行程。25 cm 和最终段出现保护停止，不能概括成八段全部无误差通过。

本次拉屉只有命令与离散检查点、32 帧 RGB 和对应状态/深度；没有完整连续运动轨迹。现场人工扶稳，没有量化辅助力。不能由此推导关屉、松爪撤手或从原始位置自动接近已完成真机验收。

原全局 SQLite 包含其他药品及实验数据，未直接上传。原始 JSON 和 manifest 是交接的主索引；新采集运行时会在本包的数据根目录创建新的 SQLite 目录索引。
